HomeLab General

Introducción

Un HomeLab es un entorno de servidor personal donde se ejecutan servicios propios de forma completamente local, sin depender de terceros ni de la nube. En mi caso, lo monté como extensión natural de mi proyecto y mi formación en ASIX: si voy a administrar sistemas en producción, primero necesito un laboratorio real donde poder romper cosas, arreglarlas y aprender.

El proyecto empezó con el proyecto de IA en local en mi PC personal y ahora consegui un equipo viejo y limitado con el que experimento, aprendo y hago que mis necesidades tecnologicas sean mas sencillas. Ahora gestiona desde el DNS de mi red doméstica hasta el almacenamiento de fotos, pasando por monitorización continua de todos los servicios.

Todos los datos permanecen en mi red local. Ningún servicio envía información a servidores externos. Solo accedo desde el exterior con VPN.

Objetivo

El objetivo principal del HomeLab es triple:

Aprendizaje práctico

Replicar entornos de producción reales para practicar administración de sistemas, redes y ciberseguridad antes de enfrentarlos en el mundo laboral.

Soberanía de datos

Eliminar la dependencia de servicios cloud (Google Photos, Dropbox, etc.) manteniendo el control total de mis datos personales y dinero.

Experimentación

Tener un entorno seguro donde probar tecnologías nuevas, configuraciones de red avanzadas y proyectos sin miedo a romper nada crítico.

¿Qué me aporta?

Gestionar un HomeLab personal esta dando habilidades que difícilmente se aprenden en el aula:

Redes reales

DNS, DHCP, reglas de firewall cosas que se configuran de verdad, con consecuencias reales si algo falla.

Docker en producción

Despliegue, actualización y mantenimiento de contenedores, compose files, volúmenes y networking entre servicios.

Seguridad aplicada

Hardening de servicios, logs de auditoría y certificados SSL locales

Troubleshooting

Diagnóstico de fallos reales, análisis de logs, depuración de problemas de red y recuperación ante fallos de hardware.

¿Cómo lo administro?

La administración se realiza principalmente desde la terminal vía SSH, complementada con interfaces web para los servicios más visuales:

# Acceso al servidor principal
ssh izan@homelab.local -p 22
# Ver estado de contenedores Docker
docker ps --format
"table {{.Names}}\t{{.Status}}\t{{.Ports}}"
# Actualizar todos los servicios
docker compose pull && docker compose up -d

Accedo via SSH cuando lo he de administrar, el protocolo mas seguro actualmente, tengo un Wake-on-lan en un script para levantar el PC con IA local, también documento cada actualización y una tarea con cron para reinciar el servidor, despues de un largo trabajo todos merecemos un descanso.

Monitorización

La monitorización es una parte crítica de cualquier infraestructura. En el HomeLab uso tres capas complementarias: métricas en tiempo real, comprobación de disponibilidad de servicios y alertas de hardware.

Netdata

Netdata es el motor de monitorización en tiempo real del servidor. Con resolución de 1 segundo, captura métricas de CPU, RAM, disco, red, temperatura y procesos de todos los contenedores Docker.

Métricas de sistema

Uso de CPU por núcleo, uso de RAM, I/O de disco, temperatura de componentes y carga del sistema en tiempo real...

Contenedores Docker

Uso de CPU y RAM por contenedor, estado de health checks y detección automática de contenedores que consumen recursos anormales.

# Despliegue de Netdata con soporte Docker
docker run -d --name=netdata \
--pid=host \
--network=host \
-v netdataconfig:/etc/netdata \
-v netdatalib:/var/lib/netdata \
-v /etc/passwd:/host/etc/passwd:ro \
-v /var/run/docker.sock:/var/run/docker.sock:ro \
--cap-add SYS_PTRACE \
--security-opt apparmor=unconfined \
netdata/netdata

Aviso de disco dañado (S.M.A.R.T.)

Mis discos están monitorizados con smartmontools. Un script cron diario analiza el estado S.M.A.R.T. de cada disco y envía una alerta por email si detecta sectores defectuosos, errores de lectura o temperatura elevada.

Los discos HDD tienen una tasa de fallo elevada pasados los 3-5 años. La monitorización S.M.A.R.T. permite detectar fallos inminentes antes de perder datos.

smartmontools cron diario Alertas email

DNS PiHole

PiHole actúa como servidor DNS de toda la red doméstica, interceptando peticiones a dominios de publicidad, rastreo y malware antes de que lleguen a los dispositivos. Con listas de bloqueo actualizadas automáticamente cada semana, filtra entre el 20% y el 40% del tráfico DNS total.

Bloqueo de anuncios

Bloqueo de publicidad a nivel de red para todos los dispositivos conectados: PCs, móviles, Smart TVs y consolas, sin instalar nada en cada uno.

~25% peticiones bloqueadas

Galería Immich

Immich es la alternativa self-hosted a Google Photos que uso para almacenar y gestionar todas mis fotos y vídeos. La aplicación móvil hace backup automático en tiempo real a mi servidor, y nunca más una foto mía pasa por servidores de terceros.

Immich incluye reconocimiento facial con IA, búsqueda por contenido, generación automática de álbumes y mapa de ubicaciones, todo ejecutándose localmente.

Backup automático

La app de Immich para Android hace backup automático de cada foto y vídeo nuevo en cuanto el móvil se conecta a la WiFi doméstica.
