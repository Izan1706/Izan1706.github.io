General HomeLab

Introduction

A HomeLab is a personal server environment where you run your own services completely locally, without depending on third parties or the cloud. In my case, I set it up as a natural extension of my project and my ASIX training: if I'm going to manage production systems, I first need a real laboratory where I can break things, fix them and learn.

The project started with the local AI project on my personal PC and now I got an old and limited equipment with which I experiment, learn and make my technological needs simpler. It now manages everything from my home network DNS to photo storage, through continuous monitoring of all services.

All data remains on my local network. No service sends information to external servers. I only access from outside with VPN.

Objective

The main objective of the HomeLab is threefold:

Practical learning

Replicate real production environments to practice system administration, networks and cybersecurity before facing them in the work world.

Data sovereignty

Eliminate dependence on cloud services (Google Photos, Dropbox, etc.) while maintaining total control of my personal data and money.

Experimentation

Have a safe environment to test new technologies, advanced network configurations and projects without fear of breaking anything critical.

What does it give me?

Managing a personal HomeLab is giving me skills that are difficult to learn in the classroom:

Real networks

DNS, DHCP, firewall rules - things that are configured for real, with real consequences if something fails.

Docker in production

Deployment, update and maintenance of containers, compose files, volumes and networking between services.

Applied security

Service hardening, audit logs and local SSL certificates

Troubleshooting

Real failure diagnosis, log analysis, network problem debugging and recovery from hardware failures.

How do I manage it?

Administration is done mainly from the terminal via SSH, complemented with web interfaces for the more visual services:

# Access to main server
ssh izan@homelab.local -p 22
# Check Docker container status
docker ps --format
"table {{.Names}}\t{{.Status}}\t{{.Ports}}"
# Update all services
docker compose pull && docker compose up -d

I access via SSH when I need to manage it, currently the most secure protocol. I have a Wake-on-lan script to boot the PC with local AI. I also document each update and have a cron task to restart the server - after a long job, we all deserve a break.

Monitoring

Monitoring is a critical part of any infrastructure. In the HomeLab I use three complementary layers: real-time metrics, service availability checks, and hardware alerts.

Netdata

Netdata is the real-time monitoring engine of the server. With 1-second resolution, it captures metrics of CPU, RAM, disk, network, temperature and processes of all Docker containers.

System metrics

CPU usage per core, RAM usage, disk I/O, component temperature and system load in real time...

Docker containers

CPU and RAM usage per container, health check status and automatic detection of containers consuming abnormal resources.

# Deploy Netdata with Docker support
docker run -d --name=netdata \
--pid=host \
--network=host \
-v netdataconfig:/etc/netdata \
-v netdatalib:/var/lib/netdata \
-v /etc/passwd:/host/etc/passwd:ro \
-v /var/run/docker.sock:/var/run/docker.sock:ro \
--cap-add SYS_PTRACE \
--security-opt apparmor=unconfined \
netdata/netdata

Disk failure alert (S.M.A.R.T.)

My disks are monitored with smartmontools. A daily cron script analyzes the S.M.A.R.T. status of each disk and sends an email alert if it detects bad sectors, read errors or high temperature.

HDD disks have a high failure rate after 3-5 years. S.M.A.R.T. monitoring allows detecting imminent failures before losing data.

smartmontools daily cron Email alerts

DNS PiHole

PiHole acts as DNS server for the entire home network, intercepting requests to advertising, tracking and malware domains before they reach the devices. With blocklists updated automatically every week, it filters between 20% and 40% of total DNS traffic.

Ad blocking

Network-level ad blocking for all connected devices: PCs, mobiles, Smart TVs and consoles, without installing anything on each one.

~25% blocked requests

Custom local DNS

Local DNS records to access HomeLab services with friendly names: immich.local, netdata.local...

# docker-compose.yml — PiHole
services:
pihole:
image: pihole/pihole:latest
ports:
- "53:53/tcp"
- "53:53/udp"
- "8053:80/tcp"
environment:
TZ: 'Europe/Madrid'
WEBPASSWORD: '**********'
volumes:
- './etc-pihole:/etc/pihole'
- './etc-dnsmasq.d:/etc/dnsmasq.d'
restart: unless-stopped
