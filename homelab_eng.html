General HomeLab

Introduction

A HomeLab is a personal server environment where own services are run completely locally, without relying on third parties or the cloud. In my case, I set it up as a natural extension of my project and ASIX training: if I am going to manage production systems, I first need a real lab where I can break things, fix them, and learn.

The project started with the local AI project on my personal PC and I later acquired an old, limited machine to experiment, learn, and make my technological needs simpler. It now manages everything from my home network DNS to photo storage, plus continuous monitoring of all services.

All data stays on my local network. No service sends information to external servers. I only access from outside via VPN.

Objective

The main objective of the HomeLab is threefold:

Hands-on learning

Replicating real production environments to practise systems administration, networking, and cybersecurity before facing them in the workplace.

Data sovereignty

Eliminating dependency on cloud services (Google Photos, Dropbox...) while maintaining total control over my personal data.

Experimentation

Having a safe environment to test new technologies, advanced network configurations, and projects without fear of breaking anything critical.

What does it give me?

Managing a personal HomeLab is building skills that are hard to learn in a classroom:

Real networking

DNS, DHCP, firewall rules — things configured for real, with real consequences if something fails.

Docker in production

Deployment, updating, and maintenance of containers, compose files, volumes, and networking between services.

Applied security

Service hardening, audit logs, and local SSL certificates.

Troubleshooting

Real fault diagnosis, log analysis, network problem debugging, and hardware failure recovery.

How do I manage it?

Administration is primarily done from the terminal via SSH, complemented by web interfaces for the more visual services:

# Access to main server
ssh izan@homelab.local -p 22

# Check Docker container status
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"

# Update all services
docker compose pull && docker compose up -d

Security

Security is a priority in the HomeLab. I implemented measures such as firewall, network monitoring, and regular updates to protect all services. Additionally, I perform periodic audits using NMAP and Lynis after every major change.

Lynis — Security Auditing

Lynis is a security auditing tool I use to evaluate my system's configuration. It scans the system and provides a detailed report with a score and recommendations to improve security. It is an essential tool for keeping the HomeLab secure and protected against potential threats.

Monitoring

Monitoring is a critical part of any infrastructure. The HomeLab uses three complementary layers: real-time metrics, service availability checks, and hardware alerts.

Netdata

Netdata is the real-time monitoring engine for the server. With 1-second resolution, it captures CPU, RAM, disk, network, temperature, and process metrics for all Docker containers.

System metrics

Per-core CPU usage, RAM, disk I/O, component temperature, and system load in real time.

Docker containers

Per-container CPU and RAM usage, health check status, and automatic detection of abnormal resource consumption.

# Deploy Netdata with Docker support
docker run -d --name=netdata \
  --pid=host --network=host \
  -v netdataconfig:/etc/netdata \
  -v netdatalib:/var/lib/netdata \
  -v /etc/passwd:/host/etc/passwd:ro \
  -v /var/run/docker.sock:/var/run/docker.sock:ro \
  --cap-add SYS_PTRACE \
  --security-opt apparmor=unconfined \
  netdata/netdata

Disk Failure Alert (S.M.A.R.T.)

Disks are monitored with smartmontools. A daily cron script analyses the S.M.A.R.T. status of each disk and sends an email alert if it detects bad sectors, read errors, or elevated temperature.

HDDs have an elevated failure rate after 3-5 years. S.M.A.R.T. monitoring allows detecting imminent failures before data is lost.

smartmontools daily cron Email alerts

DNS PiHole

PiHole acts as the DNS server for the entire home network, intercepting requests to advertising, tracking, and malware domains before they reach devices. With blocklists updated automatically every week, it filters between 20% and 40% of total DNS traffic.

Ad blocking

Network-level ad blocking for all connected devices: PCs, phones, Smart TVs, and consoles — no installation needed on each device.

~25% requests blocked

Custom local DNS

Local DNS records to access HomeLab services with friendly names: immich.local, netdata.local...

# docker-compose.yml — PiHole
services:
  pihole:
    image: pihole/pihole:latest
    ports:
      - "53:53/tcp"
      - "53:53/udp"
      - "8053:80/tcp"
    environment:
      TZ: 'Europe/Madrid'
      WEBPASSWORD: '**********'
    volumes:
      - './etc-pihole:/etc/pihole'
      - './etc-dnsmasq.d:/etc/dnsmasq.d'
    restart: unless-stopped
